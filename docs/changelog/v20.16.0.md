# CryptoEdge v20.16.0

## Ślad decyzji obejmuje odrzucenia

Etap trzeci migracji. Cel: odpowiedzieć na „czemu nie weszliśmy w ETH o 14:32"
jednym zapytaniem zamiast czytaniem 80 tysięcy linii konsoli.

- `decision_id` powstaje teraz w `DecisionPipeline.analyze()`, przy snapshocie,
  a nie dopiero przy zapisie telemetrii. Wcześniej odrzucenie i późniejsze
  przyjęcie tej samej oceny dostawały różne identyfikatory.
- Wiersz telemetrii niesie `snapshot_id` i `decision_ts_ms`, więc odrzucenie
  wskazuje stan rynku, który je wywołał. Wcześniej było samotnym napisem.
- Stemplowanie jest przez `setdefault`, więc identyfikator nadany wyżej
  zostaje. Runtime i replay idą przez ten sam `DecisionPipeline`, więc jedna
  zmiana pokrywa obie ścieżki.

## Trzy odrzucenia były niewidoczne

`log_reject()` zapisuje telemetrię tylko wtedy, gdy dostanie `signal=`.
Trzy wywołania go nie przekazywały, więc te odrzucenia istniały wyłącznie
w 30-elementowym buforze w pamięci i w tekście konsoli:

- `SIZE_TOO_SMALL(...)` — realnie występujące, widoczne w logach produkcyjnych
- `PAPER_TRADER_FORBIDDEN_IN_LIVE`
- `LIVE_NOT_WIRED` — **kod nieosiągalny**, patrz niżej

Test `test_no_caller_forgets_the_signal` pilnuje, żeby żadne przyszłe
wywołanie nie zgubiło telemetrii.

## Martwy kod w bramce LIVE

W `open_position()` dziesięć linii siedziało **za** bezwarunkowym
`return None` i nigdy się nie wykonało. Sugerowały, że LIVE ma dwie różne
bramki, podczas gdy działa wyłącznie pierwsza. Usunięte — zachowanie bez
zmian, bo `PaperTrader` w LIVE i tak był blokowany linijkę wcześniej.

## `tools/why.py`

```
python tools/why.py ETH                # ostatnie decyzje dla ETH
python tools/why.py ETH --at 14:32     # co było wiadomo o tej godzinie
python tools/why.py --summary          # lejek odrzuceń
python tools/why.py --id 3f2a...       # pełen ślad jednej decyzji
```

Narzędzie jest uczciwe wobec dedupe: powtórzone odrzucenia z tym samym
powodem są scalane (`DECISION_TELEMETRY_DEDUPE_SECONDS`, domyślnie 300 s),
więc przy `--at` podaje wiek wiersza względem pytanej godziny. Brak wpisu
dokładnie o 14:32 nie znaczy, że bot nie patrzył — znaczy, że odpowiedź się
nie zmieniła.

Pierwsze uruchomienie na realnej telemetrii (25 478 decyzji): 33 wejścia,
25 445 odrzuceń, z czego `V2_RANGE_SKIP` 43,2%, `V2_NO_15M_TRIGGER` 23,3%,
`V2_4H_CTX_OPPOSE` 10,8%, `V2_SL_TOO_TIGHT_VS_COST` 10,0%.

## Poprawione testy

- `RiskStub.log_reject` w `test_v16_regressions` nie przyjmował `signal=`,
  przez co `TypeError` ginął w `except Exception` wokół telemetrii i
  odrzucenie po cichu nie było zapisywane. Stub odpowiada teraz realnej
  sygnaturze.
- `test_runtime_and_replay_share_the_same_decision_pipeline` porównuje treść
  decyzji z pominięciem pól śladu — dwa niezależne przebiegi mają różne
  `decision_id` z definicji.
