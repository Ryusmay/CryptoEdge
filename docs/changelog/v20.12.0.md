# CryptoEdge v20.12.0

## Modular monolith

- Wprowadzono typowaną, niemutowalną domenę dla snapshotów, decyzji, ryzyka,
  zleceń, filli, pozycji i zdarzeń.
- Wydzielono publiczne granice `market_data`, `strategy`, `risk`, `execution`,
  `portfolio`, `replay`, `telemetry`, `services`, `apps` i `infrastructure`.
- Dodano wspólny `DecisionPipeline`; runtime i replay V2 wykonują aktywną
  strategię przez ten sam entrypoint i ten sam publiczny import silnika.
- Dodano idempotentny `FillLedger`, agregację partial fills, VWAP i fee oraz
  kontrolowany lifecycle z ochroną przed duplikatem i overfillem.
- Runtime publikuje modułowy health dla danych, strategii, ryzyka, execution,
  reconciliation i portfela przez `/health` oraz `/api/health`.
- UI pozostaje klientem lokalnego API; nie otrzymał zależności od backendu.
- Legacy moduły pozostają adapterami kompatybilności, dzięki czemu migracja nie
  zmienia progów strategii ani zachowania otwartych pozycji.

## Hardening granic

- Snapshoty odrzucają niezamknięte świece i jawne timestampy z przyszłości.
- Kontrakty finansowe odrzucają `NaN`, nieskończoność i niepoprawne wartości.
- Metadane rozszerzeń nie mogą nadpisać pól kanonicznych decyzji, ryzyka,
  zlecenia, fillu ani pozycji.
- Adapter strategii serializuje tymczasowe podpięcie danych, eliminując
  cross-symbol data bleed podczas równoległej analizy.
- Bramka execution jest domyślnie zamknięta; PAPER nie tworzy portu LIVE.
- Submit wymaga jawnej fabryki zlecenia przeliczającej USD na kontrakty.
- Reconciliation oraz nieznany stan zlecenia działają fail-closed.
- Fill ledger ma trwały, atomowy zapis i zachowuje idempotencję po restarcie.
- Risk sizing uwzględnia mnożnik PANIC przed projected-loss i decyzją wejścia.
- Konfiguracja PAPER po restarcie normalizuje także wartości tekstowe.
