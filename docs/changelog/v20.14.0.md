# CryptoEdge v20.14.0

## Replay był martwy od v20.12.0

Zamrożona domena wjeżdżała do kodu legacy. `MarketSnapshot` zamraża ramki na
`MappingProxyType` i `tuple`, a `LegacyV2StrategyAdapter` podawał je wprost do
`DayTradingEngineV2`. Silnik buduje z nich `V2MarketSnapshot` i woła
`.to_dict()`, czyli `dataclasses.asdict()`, które próbuje `deepcopy` i wywala
się na `TypeError: cannot pickle 'mappingproxy' object`.

Skutkiem był martwy **każdy** replay przechodzący przez
`production_signal_provider_v2`: walk-forward, `run_portfolio_replay_v2`
i zakładka Replay w nowym UI. Żaden z 890 testów tego nie łapał, bo żaden nie
przepuszczał zamrożonego snapshotu przez adapter — testy adaptera używały
zwykłych dictów, a testy replayu omijały pipeline.

- Adapter rozmraża ramki na granicy, czyli tam, gdzie należy: domena zostaje
  niezmienna, kod legacy dostaje zwykłe dicty i listy.
- Rozmrażanie jest leniwe i memoizowane per `evaluate()` — konwersja siedzi
  w gorącej pętli replayu i nie może się powtarzać przy każdym `_fetch`.
- Brak ramki nadal spada do `original_fetch`, więc semantyka runtime bez zmian.
- `tests/test_legacy_strategy_adapter_thaw.py` pilnuje całej pułapki, łącznie
  z tym, że `asdict()` na zamrożonych ramkach faktycznie rzuca.

## Bramka parytetu

`tools/parity.py` — jedno wywołanie, jednoznaczny wynik. Każdy etap migracji
do modułów ma przez nią przejść.

```
python tools/parity.py                   # porównaj z baseline
python tools/parity.py --write-baseline  # zapisz nowy punkt odniesienia
python tools/parity.py --days 90         # pełny przebieg (~15 min)
```

- Porównuje transakcje **oraz lejek odrzuceń**. Sam `net_r` nie wystarcza:
  refaktor może przesunąć powód odrzucenia bez zmiany wyniku końcowego i taka
  zmiana też ma być widoczna.
- Diff transakcji jest kluczowany po `(entry_i, symbol)`, więc przesunięcie
  jednej pozycji nie rozjeżdża całej listy.
- `config_hash` obejmuje wszystkie skalarne ustawienia z `config.py`, a lista
  `watched` pokazuje typowe progi wprost. Zmiana progu jest widoczna jako
  zmiana konfiguracji, nie jako tajemnicza różnica w wynikach.
- Domyślnie 5 par × 30 dni (~5 min) na bundlach, które są już w repo — baseline
  i jego dane wejściowe są wersjonowane razem, więc bramka jest odtwarzalna na
  czystym klonie.
- Baseline: `tests/baselines/parity_v2.json` (64 transakcje, net -6.5366R,
  OOS +2.2130R, config `bee6af3c6d61120d`).

Dwa niezależne przebiegi dają identyczny wynik — bramka jest deterministyczna.
