# v20.69.0 — dziewięć testów, które nigdy się nie uruchomiły, i `run_tests.py` kończący kodem 1

## Co znalazłem

Sprawdzałem, czy CI wstawione w v20.67.0 faktycznie przejdzie, zanim zapali się
czerwona odznaka na publicznym repozytorium. Nie przeszłoby.

`python run_tests.py` — polecenie, które README i `AGENTS.md` podają jako
kanoniczne — **kończyło się kodem 1** na czystym repozytorium:

```
--- tests.test_ui_read_models FAILED ---       Ran 0 tests
--- tests.test_ui_trade_projection FAILED ---  Ran 0 tests
Ran 1355 tests in isolated modules
FAILED (failures=0, errors=0, modules=2)
```

Zero błędów, zero niepowodzeń — a mimo to porażka, bo dwa moduły nie zawierały
**ani jednego testu do uruchomienia**.

## Przyczyna

Oba pliki przyszły z gałęzi UI napisane w stylu pytest: gołe funkcje
`def test_...` ze zwykłym `assert`. `run_tests.py` używa loadera `unittest`,
który takich funkcji **nie zbiera** — widzi moduł, nie widzi w nim testów.
`loadTestsFromName(...).countTestCases()` zwracał dla obu **0**.

Pytest nie jest zainstalowany i nie jest zadeklarowany w `requirements.txt`.
Czyli te dziewięć asercji **nie wykonało się nigdy — w żadnym runnerze, na
żadnej maszynie.** Pliki wyglądały jak pokrycie testowe i nim nie były.

Sprawdzone osobno, że to nie wina `QT_QPA_PLATFORM=offscreen` z CI: bez tej
zmiennej wynik jest identyczny.

## Naprawa

Oba pliki opakowane w `unittest.TestCase`. Konwersja jest mechaniczna
i celowo minimalna — te same ciałka, te same asercje (zwykły `assert` działa
w `unittest` tak samo, podnosi `AssertionError`), tylko klasa wokół.

Nie przepisywałem asercji na `self.assertEqual`, choć byłoby ładniej. Naprawa
uruchamiania testu i zmiana jego treści to dwie różne rzeczy; zrobione razem
dałyby zmianę, o której nie da się powiedzieć, czy test przeszedł dlatego,
że kod działa, czy dlatego, że asercja zelżała.

## Wynik

Wszystkie dziewięć odzyskanych testów **przechodzi** — nie było w nich
ukrytego długu, tylko martwe uruchamianie.

```
Ran 1364 tests in isolated modules
OK
```

W warunkach CI (`QT_QPA_PLATFORM=offscreen`, `PYTHONHASHSEED=0`), kod
wyjścia **0**. Odznaka będzie zielona przy pierwszym uruchomieniu.

## Wniosek na przyszłość

„Suita jest zielona" znaczyło u mnie przez kilka wersji „`unittest discover`
nie zgłasza błędów". To nie to samo, co „kanoniczne polecenie z README kończy
się zerem". Różnica między tymi dwoma zdaniami to były dwa martwe moduły
i kod wyjścia 1 na repozytorium, które właśnie ma iść do oceny.

Liczba testów też nie jest miarą pokrycia: 1355 wyglądało solidnie, a dziewięć
z nich było atrapami, bo nikt nie sprawdził, czy runner je w ogóle widzi.
