# CryptoEdge v20.9.0

- Swing V2 jest zuzywany dopiero po rzeczywistym fillu, nie podczas oceny sygnalu.
- PAPER i replay wysylaja wspolne zdarzenie `notify_entry_fill`.
- Replay korzysta z izolowanej kalibracji expectancy i wspolnego finalnego filtra Net R.
- Portfel V2 jest wyrownany po wspolnych timestampach 5m, nie po indeksie tablicy.
- Pozycje otwarte na koncu IS/OOS sa rozliczane mark-to-market i jawnie raportowane.
- Maker/taker fee zalezy od rodzaju fillu; latency i cancel latency wplywaja na execution clock.
- Probabilistyczny touch jest deterministyczny dla stalego random seed.
- Niewspierane execution 1m/L2 konczy sie jawnym bledem zamiast udawac zgodnosc.
- Raport zawiera reject funnel, config snapshot, code/config/data hash i experiment ID.
